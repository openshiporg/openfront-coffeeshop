## Blocker

### QA-001: A freshly onboarded store cannot sell anything online: every item fails with "Can't add this right now"
- **Area:** storefront / onboarding
- **URL:** https://openfront-coffee-shop-production.up.railway.app/ (any `+` quick-add, any item page "Add to cart")
- **Steps:** Open the storefront during opening hours (tested 14:32 EDT, "Open until 5 PM"). Tap `+` on the Almond Croissant hero, or call `quoteCafeOrder` for any menu item.
- **Expected:** The item is added to the cart and the customer can check out.
- **Actual:** Quick-add shows "Can't add this right now." The public `quoteCafeOrder` returns `{"errors":[{"message":"Unexpected error." ...}]}` for **every** item (Almond Croissant, Cardamom Cold Brew, House Blend Beans tested). Root cause: onboarding creates all 8 inventory items with `currentStock = 0` (the seed sets `parLevel`/`reorderPoint` but no opening stock). Storefront quotes then fail `assertCafeRequirementsInStock` ("Part of this order is sold out right now"). Meanwhile the menu, the item pages and the dashboard Menu manager all show the items as available (green "On", `+` buttons), so neither merchant nor customer can tell why. Ordering worked only after stock was received by hand through four purchase orders (see QA-007).
- **Likely files:** `features/platform/onboarding/lib/seed.json` (inventory items have no opening stock; seeding should create opening lots or stock movements), onboarding seeding code under `features/platform/onboarding/`, `features/keystone/mutations/coffeeBoundaryQueries.ts:566-567`, `features/keystone/mutations/cafeStorefrontPolicy.ts:52-60`.

## Major

### QA-002: The storefront and Menu manager show sold-out items as orderable
- **Area:** storefront / dashboard
- **URL:** `/`, `/menu/[id]`, `/dashboard/platform/menu`
- **Steps:** Leave an item's inventory at 0 (for example House Blend Beans, or anything after QA-001). View the menu and the item page, then open the Menu manager.
- **Expected:** The item reads "Sold out" on the storefront, with no add button. The Menu manager flags it as out of stock.
- **Actual:** The storefront shows `+` / "Add to cart" and only fails after the tap. The Menu manager shows a green dot and the toggle "On". Availability is driven only by `MenuItem.available`, and modifiers by `inStock`. Recipe and inventory stock is never considered (Oat Milk at 0 gal is still offered as a selectable milk option).
- **Likely files:** `features/storefront/lib/data/menu.ts` and the `getCoffeeMenu` resolver, `features/storefront/components/MenuQuickAdd.tsx`, `features/storefront/components/AddToCartCustomizer.tsx`, `features/platform/menu/components/MenuManager.tsx`.

### QA-003: Customers never see why an add or an order failed; resolver errors are masked as "Unexpected error."
- **Area:** storefront
- **URL:** `/` (quick add), `/menu/[id]`, `/checkout`
- **Steps:** Trigger any quote failure (sold out, closed, invalid modifier).
- **Expected:** A specific message, such as "Sold out right now" or "We open at 8 AM".
- **Actual:** GraphQL returns "Unexpected error." and the UI shows the generic "Can't add this right now." or "We couldn't price this cart right now. Some items may be unavailable or sold out." The resolvers already throw good messages (`"Part of this order is sold out right now"`, `"Pickup ordering is closed for the store's current hours"`), but they are masked in production.
- **Likely files:** Keystone GraphQL error masking config (`keystone.ts` / `features/keystone/index.ts`), so the domain errors need to be user-safe errors. Also `features/storefront/components/MenuQuickAdd.tsx:47-56` and `CheckoutClient.tsx:22-23`.

### QA-004: Dashboard home shows "Unknown" for every model count
- **Area:** dashboard
- **URL:** https://openfront-coffee-shop-production.up.railway.app/dashboard
- **Steps:** Sign in and open Dashboard.
- **Expected:** "5 items", "1 item" and so on for each model.
- **Actual:** All 30 cards say "Unknown". Confirmed cause: the `StoreSetting` list sets `plural: "Store settings"`, so `getGraphQLNames` builds `storesettingsCount`. That field doesn't exist (the real field is `storeSettingsCount`), so the single batched count query fails validation ("Cannot query field \"storesettingsCount\" on type \"Query\"") and every count is lost. Every other count query works on its own.
- **Likely files:** `features/keystone/models/StoreSettings.ts:40` (`plural: "Store settings"`; use `graphql.plural`/a label instead, or fix name derivation), `features/dashboard/actions/getAdminMetaAction.ts:97`, `features/dashboard/actions/getListCounts.ts`. Optionally make counts fail per list rather than all at once.

### QA-007: No way to enter opening stock or a stock count; one purchase order per item
- **Area:** dashboard / onboarding
- **URL:** `/dashboard/platform/coffee-operations`, `/dashboard/inventory-items/[id]`
- **Steps:** As a new merchant, try to record what is on the shelf today.
- **Expected:** A stock count or adjustment ("set on hand"), or a multi-line delivery.
- **Actual:** `currentStock` is read-only (`InventoryItem.ts:66`). Stock can only arrive via a purchase order, and each PO holds a single inventory item and must be received in full ("partial deliveries aren't supported"). Stocking the 8 seeded items on day one takes 8 POs and 8 receipts. There is no count or adjustment path for shrinkage either, apart from waste.
- **Likely files:** `features/keystone/models/InventoryItem.ts:65-66`, `features/platform/coffee-operations/components/OperationsTaskPanel.tsx`, `features/platform/coffee-operations/actions/operations.ts`.

### QA-010: Sales tax can't be set to the store's real rate; the seed undercharges NYC tax
- **Area:** dashboard / onboarding
- **URL:** `/dashboard/platform/store-settings` (Pickup and tax)
- **Steps:** The store is in Brooklyn, NY (combined rate 8.875%). Try to enter it.
- **Expected:** 8.875% can be entered.
- **Actual:** The field is whole basis points, so 887.5 is impossible. The seed uses `887` (8.87%), so every order is under-taxed: the QA sale charged $0.99 on $11.20, where 8.875% is $0.994. The hint text "875 = 8.75%" doesn't match the seeded value.
- **Likely files:** `features/keystone/models/StoreSettings.ts:102`, `features/platform/onboarding/lib/seed.json:14,67`, tax maths in `calculateCafeTotals`.
